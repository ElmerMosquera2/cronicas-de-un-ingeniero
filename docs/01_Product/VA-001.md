# VA-001 — Crónicas de un Ingeniero

## Qué es y cómo se usa

**Crónicas de un Ingeniero** es un repositorio que reúne crónicas sobre el ejercicio de construir software. Cada crónica documenta una experiencia, una decisión, un problema, un aprendizaje o una reflexión nacida de la práctica, preservando el contexto suficiente para comprender no solo el resultado, sino también el camino recorrido.

El repositorio se organiza mediante un sistema de gobernanza autocontenido. La metodología utilizada para clasificar, relacionar y evolucionar las crónicas forma parte de este mismo repositorio y evoluciona bajo las mismas reglas que gobiernan el resto de su contenido.

La elección de un repositorio Git responde a la necesidad de conservar la historia tanto de las crónicas como de la metodología que las organiza, permitiendo que ambas evolucionen conjuntamente sin perder trazabilidad.

Aunque el repositorio constituye la fuente de verdad del proyecto, su contenido no está limitado a este medio. Cualquier representación futura —como un sitio web, una wiki generada automáticamente o un canal dedicado a narrar algunas de estas historias— será una proyección de las crónicas aquí contenidas y remitirá siempre a este repositorio como origen.

El entorno de trabajo está compuesto por **Obsidian**, **Git** y **GitHub**. Obsidian proporciona el espacio de escritura, organización y refinamiento; Git conserva la historia de cada cambio; y GitHub hospeda el repositorio y facilita su distribución y colaboración. Estas herramientas hacen posible la evolución del proyecto, pero no definen su identidad.

El nombre **Crónicas de un Ingeniero** describe mejor el espíritu del proyecto que a su autor. Aunque quien escribe estas páginas no posee un título de ingeniería, "ingeniero" se emplea aquí como una licencia narrativa: la forma más sencilla de nombrar a alguien cuya afición consiste en comprender sistemas, desmontarlos y volver a construirlos.

## Lo que no es

* No es un manual de ingeniería de software.
* No es un curso ni una colección de tutoriales.
* No es un blog tecnológico.
* No es una wiki.
* No es un repositorio de notas personales sin estructura.
* No pretende documentar toda la actividad profesional de su autor, sino únicamente aquellas experiencias que merecen convertirse en una crónica.
* No depende de una plataforma específica para existir; cualquier otro medio de publicación será una representación derivada de este repositorio.

## Alternativas cercanas y por qué esto en vez de eso

El proyecto podría haberse desarrollado como un sitio web, una wiki, una red social o incluso como parte del perfil personal de GitHub. Sin embargo, ninguna de esas alternativas sitúa la evolución del contenido como elemento central.

Una página web prioriza la publicación; una wiki delega parte de la organización en la plataforma; una red social favorece la inmediatez sobre el contexto; y un perfil personal de GitHub representa al autor antes que a la obra.

En **Crónicas de un Ingeniero**, la unidad principal es la crónica: el relato de una experiencia cuyo valor reside tanto en el resultado como en el contexto, las decisiones y los aprendizajes que la hicieron posible. El repositorio, junto con su sistema de gobernanza autocontenido, garantiza que esas relaciones permanezcan explícitas y que tanto las crónicas como la metodología que las organiza evolucionen de forma coherente, trazable y bajo un mismo historial.
